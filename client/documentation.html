API Endpoints

This API allows users to retrieve, search, add, and update Pokemon data. All data is stored in memory until the server restarts.

GET endpoints also support HEAD requests. HEAD returns the same status and headers as GET, but without a body.

GET Endpoints

/getPokemon

Returns all Pokemon in the dataset.

Relative URL: /getPokemon

Supported Methods: GET, HEAD

Query Parameters: None

Body Parameters: None

Returns: HTTP 200 OK with a JSON object containing a pokemon array with all Pokemon and their available information.

Example

Request: GET /getPokemon

Response (shortened):

{
    "pokemon": [
        {
            "id": 1,
            "name": "Bulbasaur",
            "type": ["Grass", "Poison"],
            "weaknesses": ["Fire", "Ice", "Flying", "Psychic"]
        },
        {
            "id": 2,
            "name": "Ivysaur",
            "type": ["Grass", "Poison"],
            "weaknesses": ["Fire", "Ice", "Flying", "Psychic"]
        }
    ]
}

/getPokemonByName

Finds a Pokemon by its name.

Relative URL: /getPokemonByName

Supported Methods: GET, HEAD

Query Parameters: name (String, Required)

Body Parameters: None

Returns: HTTP 200 OK with a JSON object containing one Pokemon matching the name. Returns 400 Bad Request if the name is missing or invalid, and 404 Not Found if no Pokemon matches.

Example

Request: GET /getPokemonByName?name=Pikachu

Response (shortened):

{
    "pokemon": {
        "id": 25,
        "name": "Pikachu",
        "type": ["Electric"],
        "weaknesses": ["Ground"]
    }
}

/getPokemonById

Finds a Pokemon by its ID.

Relative URL: /getPokemonById

Supported Methods: GET, HEAD

Query Parameters: id (Positive Integer, Required)

Body Parameters: None

Returns: HTTP 200 OK with a JSON object containing the Pokemon matching the ID. Returns 400 Bad Request if the ID is missing or invalid, and 404 Not Found if no Pokemon matches.

Example

Request: GET /getPokemonById?id=25

Response (shortened):

{
    "pokemon": {
        "id": 25,
        "name": "Pikachu",
        "type": ["Electric"],
        "weaknesses": ["Ground"]
    }
}

/getPokemonByType

Finds all Pokemon matching a given type.

Relative URL: /getPokemonByType

Supported Methods: GET, HEAD

Query Parameters: type (String, Required)

Body Parameters: None

Returns: HTTP 200 OK with a JSON object containing a count of matching Pokemon and a pokemon array containing those Pokemon. Returns 400 Bad Request if the type is missing or invalid, and 404 Not Found if no Pokemon match.

Example

Request: GET /getPokemonByType?type=Fire

Response (shortened):

{
    "count": 1,
    "pokemon": [
        {
            "id": 4,
            "name": "Charmander",
            "type": ["Fire"],
            "weaknesses": ["Water", "Ground", "Rock"]
        }
    ]
}

The actual response contains more than one Fire-type Pokemon.

/getWeaknesses

Returns the weaknesses of a Pokemon by name.

Relative URL: /getWeaknesses

Supported Methods: GET, HEAD

Query Parameters: name (String, Required)

Body Parameters: None

Returns: HTTP 200 OK with a JSON object containing the Pokemon's name (String) and weaknesses (Array of Strings). Returns 400 Bad Request if the name is missing or invalid, and 404 Not Found if no Pokemon matches.

Example

Request: GET /getWeaknesses?name=Pikachu

Response:

{
    "name": "Pikachu",
    "weaknesses": ["Ground"]
}

POST Endpoints

Both POST endpoints accept application/json and application/x-www-form-urlencoded request bodies. For URL-encoded requests, arrays can be submitted as comma-separated strings.

/addPokemon

Adds a new Pokemon to the dataset in memory.

Relative URL: /addPokemon

Supported Methods: POST

Query Parameters: None

Body Parameters:

  • id - Positive Integer, Required
  • name - String, Required
  • type - Array of Strings, Required
  • weaknesses - Array of Strings, Required

Returns: HTTP 201 Created with a JSON object containing a confirmation message and the new Pokemon object. Returns 400 Bad Request if data is missing, invalid, or duplicates an existing Pokemon.

Example

Request: POST /addPokemon

Request Body (JSON):

{
    "id": 152,
    "name": "Examplemon",
    "type": ["Grass"],
    "weaknesses": ["Fire"]
}

Response (201 Created):

{
    "message": "A new Pokemon has been added.",
    "pokemon": {
        "id": 152,
        "name": "Examplemon",
        "type": ["Grass"],
        "weaknesses": ["Fire"]
    }
}

/updatePokemon

Finds an existing Pokemon by name and updates its type and weaknesses.

Relative URL: /updatePokemon

Supported Methods: POST

Query Parameters: None

Body Parameters:

  • name - String, Required
  • type - Array of Strings, Required
  • weaknesses - Array of Strings, Required

Returns: HTTP 204 No Content on success, with no response body. Returns 400 Bad Request if data is missing or invalid, and 404 Not Found if the Pokemon doesn't exist.

Example

Request: POST /updatePokemon

Request Body (JSON):

{
    "name": "Pikachu",
    "type": ["Electric"],
    "weaknesses": ["Ground", "Rock"]
}

Response: 204 No Content

No JSON body is returned. The updated data can be retrieved through a GET request.

Error Responses

Invalid requests return JSON containing a message explaining the error and an ID identifying its type. 

{
    "message": "Pokemon not found.",
    "id": "pokemonNotFound"
}
